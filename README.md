# arbitrage-bot

업비트 원화 마켓 + 바이비트 USDT 무기한 김프 헷지 봇 + 바이비트 펀딩비 수익 전략
(김프 헷지: 페이퍼 / 드라이런 / 실거래, 펀딩비: 페이퍼)

> **실거래 준비는 [docs/live.md](docs/live.md)**, 서버 배포는 [docs/deploy.md](docs/deploy.md).

> **이어서 작업한다면 [HANDOFF.md](HANDOFF.md) 부터.**
> **명령어와 실행 방법은 [docs/commands.md](docs/commands.md)** 에 모아 두었습니다. 펀딩비 전략은 [docs/carry.md](docs/carry.md).

> **전략의 기준은 [docs/concept.md](docs/concept.md)** 입니다. 다른 문서나 코드와 다르면 그 문서가 맞습니다.

## 전략 한눈에
- **자본:** 업비트와 바이비트 모두 **USDT**로 들고 시작합니다. USDT는 테더 역프일 때 직접 사서 준비합니다.
- **진입:** 고른 코인(`COINS`) 중 김프가 기준 이하로 낮으면 진입합니다.
  - 업비트: USDT를 팔아 받은 원화로 코인을 삽니다.
  - 바이비트: 같은 금액만큼 숏을 칩니다(금액 헷징).
- **청산:** 김프가 올라서 수수료·전송비·펀딩비를 다 빼고도 목표 수익이 나면 양쪽을 정리합니다. 업비트는 코인을 팔아 다시 USDT를 삽니다.
- **봇 손익에 영향 없는 것:** 코인 가격, 달러 환율, 테더 프리미엄. 업비트에서 USDT → 코인 → USDT로 한 바퀴 돌기 때문에 서로 상쇄됩니다.

## 김프 계산 (업비트 USDT 가격 기준 = 코인 몫 김프)
```
김프(%) = (업비트 코인 원화 가격 ÷ (바이비트 USDT 가격 × 업비트 USDT 원화 가격) − 1) × 100
```
- **김프 사이트 숫자와 다릅니다.** 사이트는 달러 환율 기준이라 테더 프리미엄이 섞여 있습니다. 대략 `사이트 김프 ≈ 봇 김프 + 테더 프리미엄`이고, 봇은 현황 로그에 둘 다 보여줍니다.
- **판단은 실제 체결가로 합니다.** 진입·청산 판단은 세 호가창(업비트 코인, 업비트 USDT/KRW, 바이비트)을 정한 수량만큼 긁은 평균가로 합니다.
- 진입·청산 예시는 [docs/concept.md 10번](docs/concept.md#10-예시로-보는-손익-구조)에 있습니다.

## 레버리지와 자본 비율
`BYBIT_LEVERAGE`를 정하면 자본 비율이 자동으로 정해집니다(바이비트 여유분 30% 포함).

| 레버리지 | 업비트 : 바이비트 | 숏 강제청산 (대략) |
|---|---|---|
| 1배 (기본) | 43.5 : 56.5 | 가격 약 2배 |
| 2배 | 60.6 : 39.4 | 약 +49.5% |
| 3배 | 69.8 : 30.2 | 약 +32.8% |

- **리밸런싱:** 지금은 봇이 알리고 송금은 직접 합니다(실거래 단계에서 자동 송금 예정). 시작할 때와 청산 직후 비율이 목표에서 10%p 넘게 벗어나면 "어느 쪽으로 USDT 몇 개 옮기세요"라고 알립니다.
- **강제청산 대비:** 강제청산이 가까워지면(남은 상승폭 15% 미만) 증거금 추가를 긴급 경고합니다. 실제로 닿으면 업비트 코인도 즉시 정리합니다.
- **포지션 크기:** `POSITION_SIZE_USDT`를 비워두면 자동으로 정합니다(업비트 쪽 자본 × 90% ÷ 최대 포지션 수).

## 코인별 설정
진입 기준, 목표 순이익, 손절, 포지션 크기는 공통값이 기본이고, 코인별로 덮어쓸 수 있습니다.
```bash
ENTRY_PREMIUM_THRESHOLD_PERCENT=-0.5        # 공통
SOL_ENTRY_PREMIUM_THRESHOLD_PERCENT=-1.0    # SOL 만 -1.0%
```

```bash
python -m kimp.live_check      # 키·IP·권한·출금 주소·텔레그램 점검 (읽기만)
PAPER_TRADING=false python main.py                                   # 드라이런 (주문 안 냄)

```

페이퍼·드라이런·실거래는 **같은 엔진·브로커**를 쓰고 주문 실행기만 다릅니다. 순서는 [docs/live.md](docs/live.md) 5번.
**첫 실거래는 `ONE_SHOT=true`(기본 꺼짐) 로 한 바퀴만 돌려보는 것을 권합니다.**

## 실행
가상환경(venv)을 씁니다. 터미널별 설치·접속 명령은 [docs/commands.md 0번](docs/commands.md) 에 있습니다.
```bash
python -m venv .venv                  # 처음 한 번
source .venv/bin/activate             # 맥/리눅스 (윈도우: .\.venv\Scripts\Activate.ps1)

cp .env.example .env                  # 코인, 진입 기준, 레버리지, 비용 설정
python main.py                        # Ctrl+C 로 종료 (열린 포지션은 DB 에 남아 다음 실행 때 이어서 관리)
```

## 시뮬레이션 (과거 기간에 지금 전략 돌려보기)
```bash
python -m kimp.simulate --from 2026-10-01                    # 10/1 0시(한국 시간)부터 지금까지
python -m kimp.simulate --from 2026-10-01 --to 2026-10-15
python -m kimp.simulate --from 2026-10-01 --coins XRP,SOL --verbose
```
- `.env` 설정을 그대로 쓰고, 실시간 봇과 **같은 엔진**으로 1분봉을 따라 돌립니다. 강제청산은 1분봉 고가로 확인합니다.
- 과거 1분봉(업비트 코인·USDT, 바이비트), 펀딩비 이력, 달러 환율은 `data/history.db`에 저장해 두고 모자란 구간만 받습니다.
- 결과는 **확정 손익**(닫은 거래)과 **평가 손익**(끝까지 들고 있는 포지션을 마지막에 판다면)을 나눠 보여줍니다.
- **호가 간격 기록이 없으면 멈춥니다.** 과거 호가창은 거래소가 주지 않아서, 봇을 페이퍼로 돌려 쌓은 기록(`premium_snapshots`)을 씁니다. 기록이 없으면 '지금 호가' 를 쓸 수밖에 없는데 그 값은 실행마다 달라져서 숫자를 믿을 수 없습니다 ([docs/commands.md](docs/commands.md) '호가 기록 쌓기'). 그래도 보려면 `--rough-spread`.
- 슬리피지와 호가 물량은 없다고 봅니다. 대략적인 값으로 보세요.

## 추천 코인 순위 (기회 넓히기)
```bash
python -m kimp.screen                       # 최근 30일, 전체 코인 중 거래량 상위 80개, 상위 20위
python -m kimp.screen --target 0.5 --top 30 # 목표 순이익을 바꿔서 보기
python -m kimp.screen --coins XRP,SOL,DOGE  # 정한 코인끼리만 비교
```
- 코인마다 15분봉으로 봇 김프 움직임(중간값, 범위, 횡보 비율, 추세, 반감기)과 지금 호가 간격, 거래량, 물량, 펀딩비율을 봅니다.
- 진입 기준을 여러 개 넣어 백테스트해서 가장 잘 된 기준과 월 환산 수익을 보여줍니다. 지난 기간에만 맞춘 기준을 거르려고 **앞 2/3 로 고른 기준을 뒤 1/3 에 써본 결과**와 비교해 작은 값을 점수로 씁니다.
- **2단계로 돕니다:** 80개를 15분봉으로 훑고(1단계), 상위 20개만 **1분봉으로 다시 평가**합니다(2단계). 15분봉은 짧게 벌어졌다 메워진 기회를 놓쳐서 시뮬레이션 결과와 어긋납니다. `--refine-top 0` 으로 끌 수 있습니다.
- **점수 = min(전체 월수익, 검증 월수익) ÷ 자리 점유율 × 띠 가중치**
  - 자리 점유율 = 포지션을 들고 있던 시간 ÷ 전체 기간 (하한 25%). 동시 보유가 `MAX_OPEN_POSITIONS` 개뿐이라, 오래 들고 있는 코인은 다른 코인의 진입을 막습니다
  - 띠 이동(기간 4등분 구간별 중간값의 최고 − 최저)이 0.3%p 이하면 1, 1.5%p 이상이면 0
- 호가 간격은 **봇 기록 → 코인별 설정 → 지금 호가 3번 중간값 → 기본값** 순으로 정합니다 (시뮬레이션과 같은 규칙). 봇을 돌려 기록을 쌓으면 정확해집니다 ([docs/commands.md](docs/commands.md) '호가 기록 쌓기').
- 김프가 ±5% 를 넘은 적이 있는 코인(입출금 막힘 의심)은 `이상김프`로 맨 아래에 둡니다.
- 끝에 `.env` 에 붙여넣을 `COINS=` 와 코인별 진입 기준이 나옵니다. 고른 코인은 `kimp.simulate` 로 1분봉 확인을 한 번 더 하세요.
- 처음 실행은 2~3분 걸리고, 받은 캔들은 `data/history.db` 에 저장돼 다음부터 빠릅니다.

## 시세 수집 (김프·호가 기록)
```bash
python -m kimp.collect --coins CAP,SEI    # 주문 없이 김프·호가만 적습니다 (봇과 별개)
python -m kimp.collect --all              # 양쪽 거래소에 다 있는 코인 전부 (약 240개)
```
과거 호가창은 거래소가 주지 않아서, 호가 간격은 **직접 모아야** 알 수 있습니다. 30줄만 넘으면
스크리너·시뮬레이션이 추측값(0.1%) 대신 실측값을 씁니다. `data/market.db` 에 쌓이고 매매 기록과 섞이지 않습니다.

- **추천 코인·시뮬레이션·페이퍼 봇을 화면에서 실행**하고 진행 로그를 봅니다 (멈추기 가능)

파이썬 표준 라이브러리로 만든 작은 로컬 서버라 외부 프레임워크·CDN 이 없고, `127.0.0.1` 에만 열리며

## 펀딩비 수익 전략 (같이 돌아감)
- 바이비트 현물 매수 + 같은 개수 숏 → 가격 변동은 상쇄, 펀딩비(+)를 숏이 받습니다. 자본은 `CARRY_CAPITAL_USDT` 로 따로.
- `python -m kimp.carry_backtest screen` / `run --from 날짜` 로 코인 순위와 과거 결과를 봅니다.
- 2026-09~10 확인 결과는 본전 근처입니다. 자세한 건 [docs/carry.md](docs/carry.md).

| `kimp/premium.py` | 김프 계산, 호가창으로 진입·청산 체결 계산 (업비트 2단계 + 바이비트) |
| `kimp/pnl.py` | 비용 포함 손익 (USDT), 강제청산 가격 |
| `kimp/market_data.py` | 업비트·바이비트 시세 (ccxt) |
| `kimp/broker.py` | **공통 브로커** (모든 모드 같은 로직): 진입 3단계·되돌리기·청산 이어서·손익·송금·대조 |
| `kimp/executor.py` | 페이퍼 실행기 (호가로 체결 계산, 가짜 잔고) |
| `kimp/live_executor.py` | 실거래 실행기 (실제 주문·잔고·출금) / 드라이런 실행기 |
| `kimp/safety.py` | 안전장치 (비상정지, 하루 손실 한도, 연속 실패, 대조 불일치) |
