순손익 = 김프 몫 + 펀딩비 − 비용(수수료·전송비). 모두 USDT 기준입니다 — 테더 프리미엄·환율은 양쪽 다리에서 상쇄되므로 들어가지 않습니다.

용어 설명 (김프가 왜 세 개인가?)

김프 = 업비트 코인 원화가 ÷ (바이비트 가격 × 업비트 USDT 원화가) − 1 세 가지는 같은 공식에 어느 가격을 넣느냐만 다릅니다. 시장마다 가격이 둘(사는 값·파는 값)이라서 생깁니다. 호가 간격이 0 이라면 세 김프가 같은 값이 됩니다. 수수료는 어느 김프에도 포함되지 않습니다.

가운데 김프
사는 값과 파는 값의 중간. 실제로 그 가격에 거래는 안 되지만 흐름 보기엔 이것만 보면 됩니다.
진입 김프
지금 진입하면 체결될 김프 (코인 비싸게 사고 / 숏 싸게 치고 / USDT 싸게 팜). 가운데보다 높다. 이 값이 기준 아래로 내려오면 봇이 진입.
청산 김프
지금 청산하면 체결될 김프 (코인 싸게 팔고 / 숏 비싸게 닫고 / USDT 비싸게 삼). 가운데보다 낮다.
진입 − 청산
= 호가 간격 한 칸(왕복). 사자마자 팔면 날아가는 비용. 좁은 코인이 유리합니다.
필요한 상승
목표 1% + 수수료 0.31% + 호가 간격. 예) 호가 0.22% 면 김프가 약 1.53%p 올라야 1% 남습니다.

진입 김프 = 지금 사고 숏 칠 때 / 청산 김프 = 지금 팔고 숏 닫을 때. 둘의 차이가 호가 간격입니다. 코인 몫 김프만 봇 손익에 영향을 줍니다 (테더 프리미엄·환율은 상쇄).

호가 간격 기록

기록이 30건을 넘으면 스크리너·시뮬레이션이 자동으로 그 값을 씁니다. 기록이 없으면 시뮬레이션은 멈춥니다.

목표 순이익으로 관리선 맞추기 비용(수수료·호가 간격·전송비·펀딩비)을 역산해 UCL/LCL 을 정하고, 이 기간에 몇 번 왕복했는지 셉니다

위 목표로 맞추기 를 누르면, 이 코인의 실제 비용을 더해 목표 순이익이 남는 진입·청산 김프를 계산해 차트에 그립니다.

전체는 5~15분 걸립니다 (처음 받는 캔들이 많으면 더)

자세히 — 무엇을 알 수 있고 무엇은 알 수 없나
  • 알 수 있는 것 — 진입 기준·목표·동시 보유 수를 바꿨을 때 그 기간에 몇 번 진입해서 얼마 벌었을까. 코인을 고르는 근거가 여기서 나옵니다.
  • 알 수 없는 것 ①: 호가창. 거래소는 과거 호가창을 주지 않습니다 (1분봉에는 종가만 있습니다). 그래서 호가 간격을 평균값 하나로 가정합니다 — 수집 기록이 30줄을 넘은 코인은 실측 평균, 없으면 추측값 0.1%. 호가가 얇은 코인의 실제 체결 밀림은 여기서 안 보입니다.
  • 알 수 없는 것 ②: 운영. API 오류·요청 제한·송금 문제·껐다 켤 때 복구 — 전략 수학만 보기 때문에 하나도 안 나옵니다. 그건 페이퍼 봇에서 봅니다.
  • 과최적화 주의. 같은 30일로 코인을 고른 뒤 같은 30일에 돌리면 좋게 나오는 게 당연합니다. 추천 코인 탭의 검증/월(앞 2/3로 고른 기준을 뒤 1/3에 써본 값)이 더 믿을 만합니다.
  • 결과는 data/history.db 에 저장되고, 대시보드 탭에서 봇 기록과 같은 화면으로 볼 수 있습니다.

자세히 — 과거 데이터를 쓰는 게 아닙니다
  • 과거를 보지 않습니다. 지금 이 순간 업비트·바이비트 호가창을 스캔 간격마다 읽어서, 조건이 맞으면 진입하고 목표에 닿으면 청산합니다. 과거로 맞춰보는 것은 시뮬레이션 탭입니다.
  • 주문만 가짜입니다. 잔고는 DB 장부(paper_balances)만 바뀌고 돈은 나가지 않습니다. 체결가는 그 순간 진짜 호가 5단으로 계산하므로 호가가 얇은 코인의 밀림(슬리피지)이 실제처럼 나옵니다.
  • 나머지는 실거래와 같은 코드입니다. 엔진·브로커·안전장치·텔레그램·송금 판단·재시작 복구를 공유하고 실행기만 다릅니다. 그래서 실거래 직전 리허설이 됩니다.
  • 여기서만 보이는 것 — API 요청 제한, 실제 진입 빈도(하루에 몇 번 기회가 오나), 껐다 켰을 때 포지션을 이어받는지, 호가 얇은 코인의 실제 비용.
  • 한 번만 을 켜면 포지션 1개만 잡고, 청산되면 봇이 스스로 종료하며 검증 보고를 남깁니다. 최대 보유 시간을 넘기면 목표에 못 닿았어도 그 시점 시세로 정리합니다 (청산 사유 TIMEOUT) — 손익보다 '완주' 가 목적인 모드입니다.
  • 화면에서 켜는 봇은 항상 페이퍼입니다 (PAPER_TRADING=true 강제). 실거래는 터미널에서만 켤 수 있습니다.
