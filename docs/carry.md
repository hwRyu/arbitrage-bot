# 펀딩비 수익 전략 (캐리)

> 김프 헷지 전략([concept.md](concept.md))과 **따로** 돈다. 자본, 잔고, 포지션 테이블이 모두 따로다.
> 코드: `kimp/carry.py`(엔진·페이퍼 체결·실시간 시세), `kimp/carry_backtest.py`(코인 순위·시뮬레이션)

## 1. 구조
```
바이비트 현물 qty 개 매수  +  바이비트 무기한 qty 개 숏   (같은 거래소, 같은 개수)
```
- 가격이 10% 오르면 현물 +10%, 숏 −10% → 합 0. 내려도 마찬가지 → **가격 변동은 상쇄**
- 무기한 선물은 정해진 시각(코인마다 1 / 4 / 8시간)마다 롱과 숏이 펀딩비를 주고받는다.
  **펀딩비율이 + 면 롱이 숏에게 준다 → 우리(숏)가 받는다.** 이게 수익이다.
- 김프, 환율, 테더, 송금과 상관없다 (한 거래소 안에서 끝남)

## 2. 손익
```
현물 손익 = qty × (판 가격 − 산 가격)
숏 손익   = qty × (숏 진입가 − 되산 가격)
순손익     = 현물 손익 + 숏 손익 + 받은 펀딩비 − 수수료 (현물 0.1% × 2 + 선물 0.055% × 2)
```

예) 150 USDT 포지션, 하루 평균 펀딩 0.03%, 1배
| 항목 | 값 |
|---|---|
| 하루 펀딩비 | 150 × 0.03% = 0.045 USDT |
| 30일 펀딩비 | 1.35 USDT (포지션 대비 +0.9%) |
| 한 바퀴 수수료 | 0.31% = 0.47 USDT → **본전까지 약 10일** |
| 묶이는 돈 | 현물 150 + 증거금 150 = 300 USDT |
| 30일 순이익 (자본 대비) | (1.35 − 0.47) ÷ 300 = **+0.29%** |

- **자본 대비 수익은 포지션 대비 수익보다 작다.** 현물과 증거금 양쪽에 돈이 묶이기 때문이다.
  - 1배: 묶이는 돈 2배 → 자본 대비 수익은 절반
  - 2배: 1.5배 → 2/3 (대신 강제청산이 +49.5% 로 가까워짐)
- 하루 0.03% (포지션 대비) 를 꾸준히 받아도 **자본 대비 월 1% 는 안 된다.** 1배로 월 1% 를 내려면 포지션 대비 하루 약 0.07% 가 필요하다.

## 3. 진입 / 청산
| 규칙 | 기본값 | 설정 |
|---|---|---|
| 진입: 최근 72시간 하루 평균 펀딩 ≥ 기준 | 0.03%/일 | `CARRY_ENTRY_MIN_DAILY_PERCENT`, `CARRY_ENTRY_LOOKBACK_HOURS` |
| 진입: 최근 24시간 하루 평균도 ≥ 기준 (어제부터 식은 코인 거르기) | 0.03%/일 | 위와 같음 |
| 진입: 지금 펀딩비율 > 0 | | |
| 진입: 선물 매수1호가 ÷ 현물 매도1호가 − 1 ≥ 기준 (들어가자마자 손해 방지) | −0.1% | `CARRY_MIN_ENTRY_BASIS_PERCENT` |
| 청산: 최근 24시간 하루 평균 < 기준 (펀딩비를 내기 시작) | 0%/일 | `CARRY_EXIT_BELOW_DAILY_PERCENT`, `CARRY_EXIT_LOOKBACK_HOURS` |
| 강제청산 미리 피하기: 강제청산까지 남은 상승폭 < 기준이면 양쪽 정리 | 15% | `CARRY_LIQ_GUARD_PERCENT` (0 = 끔, 이때는 `LIQ_WARN_PERCENT` 경고만) |
| 청산한 코인 재진입 대기 | 24시간 | `CARRY_REENTRY_COOLDOWN_HOURS` |
| 여러 코인이 조건을 만족하면 | 72시간 평균 높은 순 | |

**강제청산이 왜 문제인가:** 숏은 격리 마진이라, 현물이 같이 올라도 숏 증거금만 따로 보고 강제청산된다.
강제청산까지 가면 증거금을 통째로 잃고, 현물은 그 뒤 가격에 팔게 된다.
- 예) ZEREBRO (2배, 2026-10): 안전장치 없이 −33 USDT → 안전장치를 넣으니 +0.10 USDT
- 예) DOOD (1배, 2026-10-21): 1시간 만에 +21% 올라 강제청산 가격(약 2배)에 바로 닿음 → −12.75 USDT. 직전 시간에는 남은 폭이 21%라 15% 안전장치에 안 걸렸다. **급등하는 소형 코인은 안전장치로도 못 막을 수 있다.**

## 4. 코인 고르기
- `CARRY_COINS` 를 적으면 그 코인만 본다.
- 비워두면 자동: 바이비트 현물 `COIN/USDT` 와 무기한 `COIN/USDT:USDT` 가 둘 다 있고, 무기한 24시간 거래대금 ≥ `CARRY_MIN_VOLUME_USDT` (5M) 이고, 지금 펀딩비율이 + 인 코인 중 높은 순 `CARRY_UNIVERSE_MAX` (40) 개
- 10분(`CARRY_REFRESH_SEC`)마다 후보와 펀딩비 기록을 새로 본다.

## 5. 자본
| 설정 | 기본값 | 뜻 |
|---|---|---|
| `CARRY_ENABLED` | true | `main.py` 실행 때 같이 돈다 (따로 스레드) |
| `CARRY_CAPITAL_USDT` | 1,000 | 이 전략용 페이퍼 자본 (처음 한 번). 전부 바이비트에 있다고 본다 |
| `CARRY_LEVERAGE` | 1 | 숏 레버리지 (김프 전략 `BYBIT_LEVERAGE` 와 같은 기본값) |
| `CARRY_MAX_POSITIONS` | 3 | |
| `CARRY_POSITION_SIZE_USDT` | 자동 | 자본 × 90% ÷ 최대 개수 ÷ (1 + 1/레버리지). 1배면 1,000 × 90% ÷ 3 ÷ 2 = 150 |
| `CARRY_SPOT_FEE_RATE` | 0.001 | 바이비트 현물 수수료 (선물은 `BYBIT_TAKER_FEE_RATE`) |

## 6. 지금까지 확인한 것 (2026-09-22 ~ 10-22, 자본 1,000 USDT)
**바이비트 펀딩비 실제 수준 (30일 하루 평균, 숏이 받는 쪽)**
- BTC·ETH 약 0.010%, XRP 0.0095%, SOL 0.0056% → 진입 기준 0.03% 에 못 미친다
- 하루 0.03% 이상은 일부 소형 코인뿐이다. 지금 펀딩비가 가장 높은 코인들은 대부분 **바이비트 현물이 없다** (주식 토큰, 신규 코인)

**시뮬레이션 (`python3 -m kimp.carry_backtest run --from 2026-09-22`, 자동 선택)**
| 설정 | 30일 손익 | 받은 펀딩 | 수수료 | 비고 |
|---|---|---|---|---|
| 2배, 안전장치 없음 | −22.90 | +5.25 | 5.33 | ZEREBRO 강제청산 −33 |
| 2배, 안전장치 15% | +0.54 | +5.14 | 5.52 | |
| 2배, 안전장치 + 재진입 대기 24시간 | −0.99 | +5.20 | 5.60 | |
| 3배 | +1.67 | +5.74 | 6.16 | |
| **1배 (기본)** | **−12.20** | +4.10 | 3.28 | DOOD 강제청산 −12.75 |
| 1배, 진입 0.05%/일 | −0.12 | +2.37 | 1.73 | |

- **결론: 지금 시장에서는 본전 근처다.** 받은 펀딩비가 수수료를 겨우 넘기고, 급등 코인의 강제청산 한 번이 그걸 다 날린다.
- 1~2일 만에 나오는 거래(BR, VVV)가 수수료만 내고 끝나는 경우가 많다.
- 해볼 만한 개선
  - 진입 기준을 올리고(0.05%) 오래 들고 가기 (거래 횟수를 줄여 수수료 아끼기)
  - 급등이 잦은 코인 빼기 (최근 변동성 필터)
  - 실거래에서는 바이비트 통합계좌(UTA) 교차 마진으로 현물을 숏 담보로 쓰면 강제청산 걱정이 크게 준다 (확인 필요)
  - 펀딩비가 높은 시기(상승장)에 다시 확인

## 7. 실행
```bash
python3 main.py                                          # 김프 전략 + 펀딩비 전략 같이 (페이퍼)
python3 -m kimp.carry_backtest screen                    # 최근 30일, 코인별 순위
python3 -m kimp.carry_backtest run --from 2026-09-22     # 과거 기간 시뮬레이션 (끝 = 지금)
python3 -m kimp.carry_backtest run --from 2026-09-22 --coins COMP,SUI --verbose
```
- 시뮬레이션은 실시간과 같은 `CarryEngine` 을 1시간봉 따라 돌린다. 과거 호가창이 없어 '지금' 호가 간격을 쓰고, 진입 판단의 '지금 펀딩비율' 은 직전 정산값으로 대신한다. 강제청산은 1시간봉 고가로 본다.
- 코인을 '지금' 거래대금으로 고르기 때문에, 그 사이 사라진 코인은 빠진다 (실제보다 좋게 나올 수 있음).
